# Система обучения сотрудников

Учебное веб-приложение для семинара по промышленной разработке. Наставник назначает курс «Приёмка товара». Сотрудник изучает вымышленный регламент, проходит три модуля и итоговый тест. Наставник видит прогресс и результаты.

## Первый запуск в Ubuntu / WSL

Нужны Go 1.26 и GCC. Драйвер SQLite включает исходники SQLite и компилирует их через CGO.

```bash
sudo apt update
sudo apt install -y build-essential
cd ~/projects/employee-training
go version
go mod download
go run ./cmd/employee-training -seed
go run ./cmd/employee-training
```

Откройте <http://127.0.0.1:8080>.

| Логин | Пароль | Роль |
| --- | --- | --- |
| `mentor` | `Mentor-demo-26` | Наставник, Анна Соколова |
| `employee` | `Employee-demo-26` | Сотрудник, Иван Петров |
| `employee2` | `Employee-demo-26` | Сотрудник, Мария Волкова |

SQLite хранит данные в `training.db` в каталоге запуска. `-seed` добавляет отсутствующие аккаунты. Назначения, пройденные модули и баллы сохраняются при повторной подготовке данных и перезапуске. После перезапуска нужно заново войти, поскольку сессии хранятся в памяти.

## Показ КТ2 за 3–5 минут

Подготовьте отдельную базу до показа. Для повтора с нуля используйте новый путь к базе.

```bash
go run ./cmd/employee-training -db kt2-demo.db -seed-showcase
go run ./cmd/employee-training -db kt2-demo.db
```

В свежей демонстрационной базе Иван начинает без курса. Марии уже назначен курс, три модуля отмечены пройденными, итоговых попыток пока нет. Команда `-seed-showcase` подготавливает модули Марии при её первом назначении. Если курс ей уже назначен, команда сохраняет имеющийся прогресс.

1. Откройте README и дерево каталогов. Покажите несколько этапов разработки командой `git log --oneline` и откройте учебный бэклог из папки с учебными материалами.
2. Войдите как `mentor` и назначьте курс Ивану. Откройте приложение в приватном окне, чтобы оставить сессию наставника открытой.
3. Под учётной записью `employee` откройте первый модуль, подтвердите чтение и сдайте тест. Для результата **4 из 5** выберите варианты **2, 1, 3, 2, 2** сверху вниз. Вернитесь в кабинет и откройте второй модуль.
4. В приватном окне выйдите из аккаунта Ивана и войдите как `employee2`. Сдайте итоговый тест с результатом **8 из 10**, выбрав варианты **2, 1, 3, 2, 1, 3, 2, 1, 1, 1** сверху вниз. Обновите кабинет наставника и покажите прогресс Ивана, первый и лучший итог Марии и статус «Курс завершён».
5. Назовите следующий этап бэклога. Это загрузка и индексация регламентов и помощник, который будет отвечать по документам с цитатами. PostgreSQL с pgvector и пилот относятся к следующим этапам.

## Устройство проекта

| Каталог | Что в нём |
| --- | --- |
| `cmd/employee-training` | Запуск HTTP-сервера и команды подготовки данных |
| `internal/web` | Маршруты, сессии, CSRF-защита и серверные шаблоны |
| `internal/training` | Материалы, вопросы, ключи и подсчёт баллов |
| `internal/store` | Схема SQLite, запросы и транзакции |

На защите можно объяснить три проверки:

- Сервер берёт идентификатор сотрудника из сессии и проверяет роль на каждом защищённом маршруте. Перед открытием модуля он читает прогресс из БД. Ключи ответов остаются на сервере.
- Первичный ключ назначения гарантирует одну запись на сотрудника. При повторном назначении SQLite сохраняет существующую запись вместе с её прогрессом.
- У каждой формы итогового теста есть подписанный идентификатор. В одной транзакции сервер проверяет, использовался ли он, считает сохранённые попытки и записывает новый результат. Первый и лучший баллы, а также статус завершения вычисляются по сохранённым попыткам.

Первая версия рассчитана на локальный запуск с учебными аккаунтами. Регистрация, восстановление пароля, админ-панель, редактор курсов и AI-помощник лежат за её пределами.

## Проверки и сборка

```bash
gofmt -l cmd internal
go test ./...
go vet ./...
go build -o employee-training ./cmd/employee-training
```

HTTP-тесты проходят путь от входа и назначения курса до итогового результата. Они проверяют роли, CSRF, пороги, повторные назначения, дубликаты и параллельные отправки, а также сохранение прогресса после переоткрытия SQLite.
